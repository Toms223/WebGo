This page shows how to install WebGo, write a minimal app, build it to WebAssembly, and generate a static site.

> The minimum usable release is `github.com/Toms223/WebGo v0.0.3`. Earlier tagged versions do not work and should not be used.

### Requirements

- Go, matching the version required by your `go.mod`.
- `github.com/Toms223/WebGo`, version `v0.0.3` or later.
- `github.com/maxence-charriere/go-app/v11`, pulled in as a dependency of WebGo. Your own code also imports it directly, for example to call `app.RunWhenOnBrowser` and `app.Route`.

### Install

Run this in your module:

```sh
go get github.com/Toms223/WebGo@v0.0.3
```

This adds WebGo to your `go.mod`. If you import `github.com/maxence-charriere/go-app/v11/pkg/app` directly in your own code, run `go mod tidy` afterward so it is added as a direct dependency too.

### Minimum main.go

A WebGo app is a normal Go program that also runs compiled to WebAssembly in the browser. The minimum version needs a component, a route, and a call to `app.RunWhenOnBrowser`:

```go
package main

import (
	"net/http"

	"github.com/maxence-charriere/go-app/v11/pkg/app"
)

type hello struct {
	app.Compo
}

func (h *hello) Render() app.UI {
	return app.Text("Hello, WebGo")
}

func main() {
	app.Route("/", func() app.Composer { return &hello{} })
	app.RunWhenOnBrowser()

	http.Handle("/", &app.Handler{
		Name: "Hello",
	})
	http.ListenAndServe(":8080", nil)
}
```

`app.RunWhenOnBrowser` starts the app when the compiled binary is running inside a browser as WebAssembly. When the same binary runs on the server, this call does nothing and execution continues to the `http.Handle` and `http.ListenAndServe` calls, which serve the page and the compiled `app.wasm` file to the browser.

This example uses a plain `app.Compo` component. To build pages with WebGo's `Page` and `ViewModel` types instead, see the pages and state guide.

### Register a route

`app.Route` associates a URL path with a function that creates the component to display at that path:

```go
func Route(path string, newComponent func() Composer)
```

Call it once per path, before `app.RunWhenOnBrowser`:

```go
app.Route("/", func() app.Composer { return &hello{} })
app.Route("/about", func() app.Composer { return &about{} })
```

Each call to `newComponent` must return a fresh instance, not a shared value.

### Build the wasm binary

The browser needs a compiled WebAssembly binary. Build it with `GOOS=js` and `GOARCH=wasm`, and place the output at `web/app.wasm`:

```sh
GOARCH=wasm GOOS=js go build -o web/app.wasm .
```

Run this from the directory containing your `main.go`. The `web` directory must exist, or be created, before this command produces `web/app.wasm`. The `app.Handler` shown above serves this file to the browser at `/web/app.wasm`.

### Generate the static site

A WebGo app can also be exported as a set of static files, for hosting without a Go server. Replace the `http.Handle` and `http.ListenAndServe` calls with `app.GenerateStaticWebsite`:

```go
func main() {
	app.Route("/", func() app.Composer { return &hello{} })
	app.RunWhenOnBrowser()

	err := app.GenerateStaticWebsite(".", &app.Handler{
		Name: "Hello",
	})
	if err != nil {
		log.Fatal(err)
	}
}
```

Then build and run:

```sh
# Build app.wasm first.
GOARCH=wasm GOOS=js go build -o web/app.wasm .

# Build and run the generator binary.
go build -o generate .
./generate
```

Running the generator binary writes the static files (`index.html`, `app.js`, `app-worker.js`, `manifest.webmanifest`, `wasm_exec.js`, and one HTML file per route) into the directory passed to `app.GenerateStaticWebsite`. The `web/app.wasm` file built in the first step is not regenerated by this call and must already be in place.
